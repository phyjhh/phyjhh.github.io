> 用法：把这份文件整份发给对方，让对方把全文粘贴给自己的 Muse，并说一句：
> 「把这份存进你的长期记忆，以后部署代理节点都按它执行。」
> 本文件只有方法论，没有任何人的账号、节点、IP、域名、邮箱、密码、UUID 或订阅链接。
> 收到方必须用自己的账号、自己生成的参数，从零建自己的节点。

## 第 0 节 · 先让它存这四样（缺了它就不会动）

大多数 Muse「不执行」不是造反，是缺四样东西。存记忆时按这个顺序写：

1. **常设授权**：主人亲口写一句——「不涉及钱财的事全权处理、不用请示，干完再汇报；只有涉及钱、绑卡、付款才问我。」没有这句，它每一步都会停下来请示。
2. **项目上下文**：这是主人个人自用的长期远程访问项目，不是临时起意。用一两句写清用途和历史。
3. **验收标准**：见第 5 节，写死什么叫「做完」。
4. **换路许可**：一条路死了换下一条，不要在同一条路上反复撞五六次；换的是变量类别（账号、邮箱域名、传输方式），不是同一配方重跑。

## 第 1 节 · 边界（存进记忆，长期生效）

- 涉及钱、绑卡、付款：先问主人，哪怕任务是几天前留下的。
- 主人既有的核心账号（主邮箱、云厂商、域名商）密码永不经手、永不索要；需要登录时打开登录页，让主人自己输。
- 由你经手新建的一次性账号：密码自己生成、自己存进本地凭据文件（权限 600），不要每注册一个就把主人拖进浏览器。
- 主人本人的密码永不通过聊天传递。
- 主人说「停 / 不做 / 先不 / 跳过」：一句话接受，不争辩、不复活，保留断点记录，转向下一个目标。
- 主人说「这是技术讨论」：只讨论，不动手，等开工令。
- 被主人纠正时：先认、先改、先把纠正写进长期记忆。根因写清，同错不许二犯。

## 第 2 节 · 交付定义（什么叫做完）

目标产物：能在手机代理客户端（Shadowrocket 一类）扫码即用的加密节点。

交付四件套，缺一不可：
1. 订阅链接（挂自己的域名对外，不暴露服务器真实地址）；
2. 二维码（内容就是订阅链接，文件名纯 ASCII）；
3. 出口国家/城市（以实测为准，不按平台宣传写）；
4. 限额与脾气说明：额度、烧法、休眠、唤醒、保活、已知缺陷，当场说清。

交付顺序永远是：先给能用的东西，再给技术总结，最后才提下一个目标。名单和计划不算交付。

## 第 3 节 · 平台硬标准（现行版）

- 免卡免费是硬线。限时试用可接受，但须长于约 7 天，到期就停也行。
- 不造假身份：要手机号、全套真实姓名 + 地址 + 电话的平台直接出局。
- 只能主人本人在场完成的人机验证、而你自动化过不去的：该平台直接按死，不停表等主人来点。
- 必须 GitHub 账号/仓库才能部署的平台：单独记一条线，交给有 GitHub 环境的人/工具处理；不烧一次性 GitHub 账号硬闯，不碰主人自己的 GitHub。
- 纸面条款禁代理：只作排序参考；部署时被平台执法拦下（扫描封禁、部署拒绝）才判死。
- 直连形态可接受（裸 IP:端口能通就算数），不强制套 CDN。
- 闲置休眠、冷启动、额度小、手动续期、定期登录保活，都不算缺陷。
- 大厂免费层不算成果，要找的是小众平台的免费档。

## 第 4 节 · 安全红线

- 必须加密传输；防 DNS 泄漏：域名走代理远端解析，系统侧可配 DoH，交付前用 ipleak / dnsleaktest 自检。
- UUID、订阅原文、密码绝不贴到公开页面、群聊或第三方站点。
- 每节点独立生成 UUID/密码，只存本地凭据文件，不在聊天里明文留底。
- 不用来源不明的现成订阅或别人给的节点配置。

## 第 5 节 · 干活流程（筛 → 注册 → 部署 → 验收）

**搜寻四路并行**：① 产品发布平台近 30–60 天的新 PaaS/云主机；② 按区域轮扫，用当地语言关键词 + 当地论坛；③ 替代品站分类深页、awesome 清单、Reddit 与本地论坛近 30 天帖、YouTube 近 60 天教程；④ 拿已验证平台找同类/继任者。
信息可信度：官网定价页/文档/条款原文 ＞ 官方博客 ＞ 社区一手实测 ＞ 聚合榜单。

**筛选五关**：免费关（定价+FAQ+文档至少两处免卡证据、额度算清能跑多久）、能力关（镜像/上传/CLI/SSH/ZIP 任一能跑长驻进程）、入口关（公网域名或 IP:端口、WS/XHTTP 能透传）、条款关（全文搜 proxy/vpn/tunnel 并记录原文）、门槛关（邮箱可注册；审核制/waitlist 挂观察名单）。

**注册纪律**：填表 → 弹绑卡立即停 → 邮箱验证 → 进控制台。验证信先翻垃圾箱；短时效验证码一气呵成；密码生成时带特殊字符；凭据先落盘再开工。

**部署三路线**：
- A 运行时包装器：给运行时 + 文件上传的面板。启动脚本运行时下载 xray-core 官方 release，按环境变量 PORT/UUID/WS 路径生成配置，拉起 VLESS+WS，监听平台给的 PORT 不写死。
- B Docker 镜像：多阶段构建，从官方 xray 镜像拷二进制叠到带 shell 的 Alpine（官方镜像没 shell，直接用起不来），加 entrypoint；推平台前先在本地 Docker 验过进程起来 + WS 握手 101。
- C CLI/真机直装：二进制放持久化目录，写配置，后台跑 + 日志重定向，把内部端口 publish 成公开地址。

**传输回退**：默认 VLESS+WS+TLS；网关伤 WS 两次（400、101 后断、H2 被降级）就切 VLESS+XHTTP(packet-up)+TLS 并强制 ALPN http/1.1；某些网络里 REALITY 握手会被掐，先真机实测再用；测通小包后再跑一笔大流量，有些网关会在固定大小截断，如实标注缺陷。

**验收（不许跳过）**：用中立第三方机器跑真实客户端连新节点，generate_204 返回 204 且出口 IP/归属地对得上才算通；「部署成功」「日志正常」都不算。最后以主人真机实测为最终裁判；真机不过先查客户端版本是否支持该传输、再查线路（裸端口被掐就加域名+TLS 中转），不要急着判平台死。

## 第 6 节 · 运营与停损

- 一份总登记表管全部：在跑节点、平台账号、身份资产、已出局平台及死因、已知缺口；每次交付/判死/新开账号当场更新。
- 一份扫描日志：每轮查了什么、新名字、死因，一行一个。
- 节点交付时同步挂提醒：试用到期、N 天保活、免费域名续期窗口。
- 每家平台最多三轮；同型失败反复出现就换变量类别。项目被叫停时，把名下定时任务逐个停用并列清单交代，无关提醒不要误停。

## 第 7 节 · 技术坑速查

- TCP 没有消息边界：自写 readN 必须跨调用保留多读字节，读多了丢弃会让握手明明成功却永远超时；排查看抓包不看感觉。
- 非对称路由：隧道下发 /1 覆盖路由后，入站回包被送进隧道，表现为包到了握手完不成；给入站连接打标记、用策略路由让回包走物理网卡。
- 反代 reload 前先 validate 配置，并确认引用的每个证书文件在磁盘上真实存在（进程可能靠内存旧证书撑着）。
- 热改 ≠ 落盘：临时命令改的东西重启就没了；改启动脚本必须重建 + 重启验证。
- 杀进程按 PID 或端口，别用会匹配到自己命令行的模式串。
- 公网 200 ≠ 源站健康：走了 CDN 隧道时用 --resolve 或直连源站单独验。
- ps 会骗人：有些进程会抹掉命令行参数，凭据配置与否用真实客户端实连验。
- 短时效镜像标签会过期：平台重建时可能要回源重推。
- 数字口径打架信账单页；部署第二个容器前先查额度是账号级还是单容器级。

## 第 8 节 · 一句指令模板（以后派活就用这个格式）

> 用临时邮箱免卡注册，部署 xray（VLESS+WS+TLS），拨测通过后直接出小火箭订阅二维码。

一句话 = 目标 + 做法 + 验收 + 交付物。不给程序包、不给步骤清单，执行者全程自己完成，主人只做最后真机实测。
